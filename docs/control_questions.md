# Контрольные вопросы ЛР3

- **Веб-сервис:** программный интерфейс, доступный по сети. Здесь HTTP API
  принимает запросы SPA/клиента и возвращает JSON, сохраняя данные в БД.
- **REST:** архитектурный стиль с ресурсами и единым интерфейсом, отсутствием
  состояния сессии в запросах, возможностью кеширования и разделением клиента
  и сервера. HTTP-метод задаёт действие над ресурсом; REST не равен «любой JSON API».
- **RPC:** вызов удалённой процедуры с именем операции и аргументами. REST
  организует интерфейс вокруг ресурсов; RPC — вокруг вызовов функций.
- **HTTP-методы:** GET читает; POST создаёт/выполняет операцию; PUT устанавливает
  состояние ресурса; PATCH частично изменяет; DELETE удаляет; HEAD аналогичен
  GET без тела; OPTIONS сообщает доступные возможности. GET/HEAD безопасны;
  PUT/DELETE идемпотентны по результату, хотя ответы повторов могут различаться.
- **Заголовки:** Content-Type описывает тело; Accept — желаемый формат ответа;
  Authorization — учётные данные; Cache-Control — кеширование; Location —
  адрес ресурса/перенаправления; Origin — источник браузерного запроса.
  Пример загрузки: multipart/form-data с boundary, а не URL файла в JSON.
- **Версии HTTP:** 1.0 — ранняя модель соединений; 1.1 — постоянные соединения
  и обязательный Host; 2 — бинарные кадры, мультиплексирование потоков и
  сжатие заголовков поверх TCP; 3 — QUIC поверх UDP с TLS, независимые потоки.
- **HTTPS:** HTTP с защищённым транспортом TLS, обеспечивающим шифрование,
  целостность и проверку сервера сертификатом. Разработка локально может
  использовать HTTP; HTTPS не меняет смысл методов REST.
- **OSI / ISO:** ISO — организация стандартизации; OSI — семиуровневая модель:
  физический, канальный, сетевой, транспортный, сеансовый, представления,
  прикладной. HTTP относится к прикладному уровню; TCP/UDP — транспортному;
  IP — сетевому. Стек TCP/IP не повторяет семь уровней OSI один к одному.
