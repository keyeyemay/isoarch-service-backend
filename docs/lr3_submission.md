# Сдача ЛР3

Запустить проект по README. Импортировать `postman_collection.json` в Postman
или Insomnia. В Postman задать working directory корнем проекта, разрешить
чтение файлов из него; используются настоящие файлы
`static/images/default_signature.png` и `static/videos/default_signature.mp4`.
При необходимости выбрать их вручную в Body → form-data.
Переменная `base_url` по умолчанию `http://localhost:8000`.

Перед сценарием GET `/api/services/draft` должен вернуть `null`.
На свежей БД демонстрационный черновик принадлежит пользователю 2, поэтому
создателю 1 не мешает. Если в прежней БД есть свой черновик, сначала осознанно
опубликовать или удалить именно его через соответствующий метод. Коллекция
сама чужие/существующие черновики не удаляет.

Запросы выполнять по порядку: `service_id` автоматически сохраняется из
ответа создания; `feed_id` — из ответа первой записи ленты. Регистрация
использует новый timestamp-логин для повторного запуска. Все тесты Postman
должны быть зелёными. Коллекция содержит ровно 10 основных запросов;
каждый из 10 методов задания представлен отдельно, включая login и logout.
GET feed дополнительно проверяет переход `?id={{feed_id}}&next=true` в Tests.
Для скриншота 6 выполните этот вариант вручную в том же запросе GET feed.
Для скриншота 10 покажите login и logout (два самостоятельных запроса).

| Скриншот | Что показать |
|---|---|
| 1 | GET списка с `c13_max=-15`, только published, `is_creator` 0/1 |
| 2 | POST multipart: title, image, video; 201, латинские имена файлов |
| 3 | GET draft без ID; поля созданного черновика |
| 4 | PUT публикации; 200, published, серверная дата formed_at |
| 5 | GET feed без ID; одна публикация и is_liked 0/1 |
| 6 | GET feed?id={feed_id}&next=true; следующая публикация |
| 7 | POST like=1; like и likes_count; для отмены отдельно показать like=0 |
| 8 | DELETE созданной услуги; 204; строка в БД остаётся, deleted_at заполнен |
| 9 | POST register; 201, пользователь без пароля |
| 10 | POST login и POST logout — отдельные заглушки |
| 11–13 | Выполнить три SELECT из `docs/lr3_select.sql` |
| 14–15 | Модели `models/` и входные/выходные схемы `api/schemas.py` |
| 16 | `get_current_user()` и его `Depends` в методах API и страниц |
| 17 | README с методами и полями таблиц |

Дополнительно открыть MinIO Console → бакет `isoarchservice`: показать
оба объекта с именами из POST. Продемонстрировать отказ чужого удаления (403),
повторного черновика/публикации (409), системного поля (422), скрытой записи (404).
Объяснить диаграмму классов и контрольные вопросы из соседнего файла.

Скриншоты должны быть сняты с реально выполненных запросов в Postman/Insomnia;
файл коллекции и автоматические тесты сами по себе не заменяют эти изображения.

Контракт обновлён по `Lab_3_updated.md`: старые снимки с `/publish`,
`/services/` и `/feed/{id}` не подтверждают текущую версию — переснимите
затронутые запросы и SELECT с `deleted_at`. Автоматические отчёты не заменяют
личный показ, скриншоты и ответы на контрольные вопросы.
